Background

背景与痛点

特征衍生与策略挖掘长期依赖人工，存在三个结构性问题
01
PAIN 01

重复造轮子

新特征想到就写 SQL，不知道字典里是否已有同口径衍生。
代价特征重复、口径不一
02
PAIN 02

流程长且易错

查表 → 写 SQL → 建表 → 评估 → 挖策略，5 段全靠手工衔接。
代价单次迭代以「天」计，字段猜错、时间穿越频发
03
PAIN 03

门槛高

IV/KS/PSI、决策树挖规则、双表验证，都要手写代码。
代价只有资深分析师能独立完成全链路
GOAL
把确定性劳动交给脚本，把创造性判断留给分析师，用 Agent 串成一句话能驱动的自动流水线。

Core Idea

核心理念

Agent 编排 + 脚本执行：创造性步骤（特征设计）由 Agent 做，确定性步骤（特征衍生 / 评估 / 策略）由脚本做。
01

入口极简

用户只说业务意图（「衍生通讯录特征并评估」），无需记命令、配参数。

02

人机分工清晰

Agent 负责「想」（读字典、探表、脑暴、写配置），脚本负责「算」（特征衍生、跑指标、挖规则）。

03

可复用可审计

每一步产出物固化为 YAML 配置 / SQL / Excel，可 review、可回溯。

Practice

用 AI 开发 Skill 的几点建议

从这套流水线里沉淀出来的三条经验
01

业务拆成单元模块，
各自封装成 Skill

把大流程切成职责单一的小单元——探表、脑暴、衍生、评估、策略各成一个 Skill，单独可用、组合可编排。粒度越清晰，越好复用、好测试、好迭代。

MODULAR · COMPOSABLE
02

先划定 Agent 的
职责与权力边界

明确让 Agent 做什么、不能做什么：创造性判断交给它，确定性动作交给脚本。白名单 / 防穿越 / 凭证隔离 用规则兜底，能力越界即报错，可控才可信。

SCOPE · GUARDRAIL
03

多向 AI 提问，
也让 AI 多提问

把需求问清楚再动手：你多追问细节，也要求 AI 在动手前反问、澄清、给方案。双向对齐比单向下令更省返工，把"我以为"提前变成"确认过"。
