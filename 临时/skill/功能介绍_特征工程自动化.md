# 反欺诈特征工程自动化 · Agent 自动挖掘 Pipeline

> 一句大白话 →（如"进行 applist 特征挖掘"）→ Agent 自动跑完 **查字典 → 查表脑暴 → 建表 → 特征评估 → 策略分析**，产出可上线的策略与美观 Excel 报告。

---

## 一、背景与痛点

反欺诈策略分析师日常最重的两块工作 —— **特征衍生** 和 **策略挖掘** —— 长期依赖人工，存在三个结构性问题：

| 痛点 | 现状 | 代价 |
|------|------|------|
| **重复造轮子** | 新特征想到就写 SQL，不知道字典里是否已有 | 特征重复、口径不一 |
| **流程长且易错** | 查表 → 写 SQL → 建表 → 评估 → 挖策略，5 段手工衔接 | 单次迭代以"天"计，字段猜错、时间穿越频发 |
| **门槛高** | IV/KS/PSI、决策树挖规则、双表验证都要手写代码 | 只有资深分析师能独立完成全链路 |

**目标**：把"确定性劳动"交给脚本，把"创造性判断"留给分析师，用 Agent 把两者串成一句话能驱动的自动流水线。

---

## 二、核心理念

> **Agent 编排 + 脚本执行**：创造性步骤（特征设计）由 Agent 做，确定性步骤（建表 / 评估 / 策略）由脚本做。

- **入口极简**：用户只说业务意图（"衍生通讯录特征并评估"），无需记命令、配参数。
- **人机分工清晰**：Agent 负责"想"（读字典、探表、脑暴、写配置），脚本负责"算"（建表、跑指标、挖规则）。
- **可复用可审计**：每一步产出物固化为 YAML 配置 / SQL / Excel，可 review、可回溯。

## 四、五步自动化流程

以"进行 applist 特征挖掘"为例：

| 步骤 | 谁做 | 动作 | 产出 |
|------|------|------|------|
| **① 查字典** | Agent | 读特征字典，列出已有 app 相关特征 | 避免重复衍生的清单 |
| **② 查表 + 脑暴 + 写配置** | **Agent（核心创造性）** | 探查源表结构 → 按思维框架设计特征 → 写出 YAML 配置 | 特征衍生 YAML |
| **③ 建 4 张表** | 脚本 | labeled/recent7d × 贷前/贷中，含复合特征合并层 | 4 张特征表 |
| **④ 特征评估** | 脚本 | 对 labeled 表算 IV/KS/PSI/最大风险倍数，分月 + 分客群 | 多 sheet 评估 Excel |
| **⑤ 策略分析** | 脚本 | 决策树挖单/多变量策略；y影响取 labeled，拒绝率取 recent7d | 策略报告 step1 + step2 |

### 关键设计：双表分工

- **labeled 表**（有 fpd_k30 逾期表现）→ 用于 **特征评估** 与策略的 **y 标签影响**
- **recent7d 表**（近 7 天全量）→ 用于策略的 **拒绝率 / 通过率影响**（反映当前真实通过率）

## 五、方法论与质量红线

### 特征设计（fraud-strategy-brainstorm）

- **五类数据源模式**：APPLIST（计数/比例/标志/时间）· 通讯录（关系网络/异常）· 通话记录（行为/关系强度）· 设备（smy/td/bs 三源融合）· 紧急联系人/地址（关联风险）
- **标签体系**：`fpd_k30` 首逾30+ · `if_out_30d/60d` 外诉 · `if_in_30d/60d` 内诉

### 质量门槛（自动筛选）

| 指标 | 含义 | 阈值 |
|------|------|------|
| **IV** | 特征区分度 | ≥ 0.02 |
| **PSI** | 特征稳定性（分月/分客群） | ≤ 0.25 |
| **Lift** | 风险提升倍数 | ≥ 2.0 |

### 工程红线（脚本强制）

- 🔒 **防穿越**：特征时间 < 样本时间，生成器自动加时间过滤
- 🔒 **聚合白名单**：仅允许 COUNT/DISTINCT/SUM/AVG/MAX/MIN/STDDEV，未知函数直接报错
- 🔒 **复合特征**：`type: composite` + `logic`，在合并层 JOIN 后计算，支持相互依赖
- 🔒 **凭证隔离**：只从 `.env` 读，代码/文档零明文账号 IP，不进 git
- 🔒 **分客群**：贷前按 `cust_group_dq`，贷中按 `cust_group_dz + new_old`

## 六、策略挖掘与验证（strategy-analysis 两步法）

### Step1 · 特征评估 + 策略挖掘

- 决策树挖规则：**1~3 个特征组合**，仅 `>`/`<` 单方向（避免局部最优）
- 策略质量：min_bad ≥ 10，覆盖率 ∈ [0.1%, 20%]，Lift ≥ 2.0
- 去重：Jaccard 相似度，按 Lift 降序
- 产出：`strategy_step1.xlsx`（执行摘要 / 有效特征 / 有效策略）

### Step2 · 近 7 天全量验证

| 指标 | 计算 | 业务含义 | 阈值 |
|------|------|----------|------|
| **命中率** | 命中数 / 总样本 | 覆盖客户比例 | 0.1%~20% |
| **通过率影响** | 误拒好客户 / 总好客户 | 误杀对业务的影响 | < 5% |
| **误报率** | 命中中的好客户 / 总命中 | 策略精准度 | < 30% |
| **稳定性** | 近 7 天每日波动 | 效果是否稳定 | PSI ≤ 0.25 |

- 通过率影响 > 10% 自动标记"高风险，需人工评审"
- 产出：`strategy_step2.xlsx`（验证摘要 / 验证后策略 / 稳定性趋势）+ 自动生成总结陈述

## 七、产出物

- **特征评估报告**：10-sheet 美观 Excel（变量描述 / 分组透视 / 综合指标 / 空值率 / PSI / IV / KS / 最大风险倍数 / 分组明细），中文表头、百分比格式、首行冻结与筛选。
- **策略报告**：step1（挖掘）+ step2（验证），含可直接进入灰度评审的策略清单。
- **可复用资产**：特征字典、YAML 配置、建表 SQL —— 沉淀为团队共享资产。

## 八、价值

| 维度 | 传统人工 | Agent 自动化 |
|------|----------|--------------|
| **单次迭代周期** | 以天计（查表→写SQL→评估→挖策略） | 一句话驱动，大幅压缩 |
| **重复劳动** | 每次从零写 SQL | 查字典去重 + 配置复用 |
| **质量一致性** | 依赖个人经验，口径易漂 | 阈值/防穿越/白名单脚本强制 |
| **人才门槛** | 需资深分析师全程 | 创造性判断保留给人，其余交给脚本 |
| **可审计性** | 散落脚本 | 配置/SQL/报告全链路可回溯 |
