# lov-model：会话内模型切换助手

## 定位
这是一个**盲切式**助手：不探测、不发任何网络请求、不读 token。它只维护一份性能降序
清单，并把"该切哪个模型"的建议告诉用户。是否真的可用，由用户切过去后从对话中直接感知
（若限流/报错，回来说一声，给下一档）。

模型切换本身由 Claude Code 原生 `/model <name>` 完成——会话内即时生效、无需 token、无需
重启。**本 skill 只给建议，由用户自己敲 `/model`，绝不代替用户执行。**

## 使用方式

第一步永远是：用 **Read 工具**读本 skill 目录下的 `models.json`，拿到 `auto_route`
（性能降序主列表）与 `manual_only`（备查白名单）。然后按场景响应：

### 场景 1：默认选最优（"帮我选模型" / "/lov-model" / "切个最好的"）
推荐 `auto_route` 第一个（最高档），输出：
> 当前最优档：`claude-opus-5`
> → 请执行： `/model claude-opus-5`
可附带把 auto_route 全列表按序列出，让用户知道降级路径。

### 场景 2：降级到下一档（"opus 限流了" / "给我下一个" / "换一档" / "报错了"）
在 auto_route 中定位用户当前所在档，推荐**它的下一档**；说明理由（当前档限流/不可用）。
若用户没说当前在哪档，就假定从最高档往下推一格，或直接问一句当前用的是哪个。
到列表末尾仍不行时，提示可尝试 `manual_only` 里的模型或检查网关。

### 场景 3：点名切换（"切 fable" / "用 gpt" / "换成 gemini"）
在 `auto_route` + `manual_only` 中匹配用户说的模型（模糊匹配，如 "fable" → `claude-fable-5`；
"gpt" → `gpt-5.6-sol`）。命中则给出 `/model <name>`。多个候选时列出让用户选。

### 场景 4：罗列（"有哪些模型" / "列表"）
分两组展示 auto_route（标注性能降序）与 manual_only，每个给出可直接用的 `/model` 命令。

## 配置：models.json
- `auto_route`：自动降级主列表，**性能从高到低**排序。降级建议按此顺序。
- `manual_only`：备查白名单（Fable、各家旗舰），供用户点名切换。
用户想调整优先级或增删模型，直接编辑这个 JSON 即可。

## 重要提醒
- **非 Claude 模型**（GPT/Gemini/Grok/DeepSeek/Kimi/GLM，均在 manual_only）切换后，
  Claude Code 的工具调用（读写文件、执行命令等 agent 操作）**兼容性无保证**，
  适合纯问答/查资料临时用，不建议用于完整编码任务。切换前应提醒用户这一点。
- 切换在**当前会话即时生效**，无需 token、无需重启 VSCode。
- 本 skill 不联网、不读凭证；若 `models.json` 读取失败，如实告知用户文件缺失并提示修复。
