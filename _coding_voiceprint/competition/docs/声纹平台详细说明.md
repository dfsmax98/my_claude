# 声纹平台详细说明

> 本文档说明当前本地声纹风险工作台的业务能力、算法链路、阈值配置、接口、数据存储、前端页面、验证结果和已知限制。文档内容基于 2026-08-22 已核验代码、配置、报告和本地测试结果整理。

## 1. 平台定位

声纹平台用于反欺诈场景下的双轨录音处理和声纹风险识别，当前形态是本地单机评估平台，覆盖以下能力：

- 客户录音上传、双轨校验、左右声道拆分。
- ASR 文本角色识别，判断客服声道和客户声道。
- 客户声道 CAM++ embedding 提取。
- embedding 质量评分，低质量样本进入人工复核。
- 客户 1:1 本人核验，当前后端为 PLDA。
- 黑产 1:N 检索，当前后端为按身份聚合的 cosine max-pooling。
- 客户 N:N 团伙声纹簇影子检测。
- 客户声纹库、黑产声纹库和人工复核队列。
- 前端工作台展示运行总览、任务、库表、模型阈值和复核操作。

当前平台适合本机受控环境下试运行、功能验证和算法评估，不适合直接暴露到公网或多人生产环境。

## 5. 客户核验流程

客户核验是平台主链路，流程如下：

1. 前端上传双轨录音和客户主键。
2. 服务校验文件后缀、文件大小、音频可读性、双声道数量和有效时长。
3. 平台保存上传文件，创建 `customer_verification` 任务。
4. 后台 worker 拆分左、右声道 WAV。
5. 左、右声道分别执行 ASR。
6. 文本角色模型判断哪个声道是客户。
7. 只对客户声道提取 CAM++ 192 维 embedding。
8. 对 embedding 做质量评分。
9. 如果客户已有活动模板，则执行客户 1:1 PLDA 核验。
10. 同时对黑产声纹库执行 1:N 检索。
11. 根据 1:1、1:N、质量和首录状态生成标签或复核任务。
12. 如果客户 1:1 通过且黑产检索清白，则自动新增客户活动模板。

### 5.1 首次客户录音

如果客户没有活动模板，平台无法自证本人，会生成一条待审核客户模板：

- 模板状态：`pending`
- 复核类型：`customer_enrollment`
- 审核通过后模板变为 `active`
- 审核拒绝后模板变为 `rejected`

### 5.2 非首次客户录音

如果客户已有活动模板：

- 质量通过、1:1 通过、黑产清白：自动新增 `active` 客户模板。
- 质量低、1:1 灰区、1:1 非本人、黑产疑似命中：生成复核任务。
- 角色识别失败或无法提取 embedding：录音进入复核。

## 6. 黑产入库流程

黑产入库使用独立入口：

1. 前端切换到黑产入库模式。
2. 上传双轨录音、黑产身份主键和审核提交人。
3. 平台执行同样的双轨拆分、ASR、角色识别、客户声道 embedding 提取。
4. 生成黑产模板，初始状态为 `pending`。
5. 创建复核任务 `black_enrollment`。
6. 人工审核通过后黑产模板变为 `active`，对应黑产身份状态更新为 `active`。

黑产模板不会自动激活，必须经过人工审核。

## 7. 模型与阈值

当前平台阈值来自 `configs/platform.json` 和冻结模型文件。

### 7.1 角色识别

| 参数 | 当前值 | 含义 |
|------|---:|------|
| 模型版本 | `role-text-v1-20260820` | 文本角色模型 |
| `abstain_threshold` | 0.8175754 | 左右声道客服概率差低于该值则拒识 |
| `min_chars` | 20 | 单声道有效文本最少字符数 |
| `min_speech_seconds` | 5.0 | 单声道有效语音最少秒数 |

角色模型输入只使用 ASR 文本，不使用客户标识、左右声道先验或呼叫方向作为预测输入。

### 7.2 质量评分

质量模型是逻辑回归模型，输入特征如下：

| 特征 | 含义 |
|------|------|
| `log_customer_speech_seconds` | 客户声道有效语音时长的对数变换 |
| `log_customer_asr_chars` | 客户声道 ASR 字符数的对数变换 |
| `role_margin` | 角色模型左右声道概率差 |
| `role_stage_count` | 角色识别阶段数 |
| `external_cohort_topk_mean` | 与外部 cohort Top-K 相似度均值 |
| `external_cohort_topk_std` | 与外部 cohort Top-K 相似度标准差 |

当前质量阈值：

```json
"quality": {
  "review_below": 0.7314997896756941,
  "cohort_topk": 50
}
```

质量分低于阈值时，样本不直接静默丢弃，而是进入人工复核或灰区处理。

### 7.3 客户 1:1

当前客户 1:1 后端：

| 参数 | 当前值 |
|------|------|
| 后端 | `plda` |
| 版本 | `customer-plda-v2-current-role` |
| PLDA 维度 | 80 |
| 拒绝阈值 | `-41.62520980834961` |
| 通过阈值 | `-14.513204574584961` |
| 灰区 | `[拒绝阈值, 通过阈值)` |

判断规则：

- 质量未通过：`review`
- PLDA 分数 `>= -14.513204574584961`：`verified`
- PLDA 分数 `< -41.62520980834961`：`not_self`
- 中间区域：`review`

当前配置采用双阈值策略，而不是单点硬判，目的是降低误拒或误放风险。

### 7.4 黑产 1:N

当前黑产 1:N 配置：

```json
"black_search": {
  "backend": "cosine_identity_max_pooling",
  "threshold": 0.9036450386047364,
  "topk": 5
}
```

处理逻辑：

- 只检索 `active` 黑产模板。
- 同一黑产身份可有多个模板。
- 每个身份取其模板集合中的最高余弦分数作为身份分数。
- Top-1 分数达到阈值时标记 `suspected`。
- 未达到阈值时标记 `clear`。

当前阈值偏保守，低误报优先。

### 7.5 N:N 团伙簇

当前 N:N 配置：

```json
"gang_cluster": {
  "threshold": 0.925,
  "topk": 2,
  "min_cluster_size": 3,
  "interval_hours": 24,
  "shadow_only": true
}
```

算法流程：

1. 只读取 `active` 客户模板。
2. 对同一客户的多个模板求平均向量。
3. 对客户平均向量做归一化，得到客户质心。
4. 计算所有客户两两余弦相似度矩阵。
5. 每个客户只保留 Top-2 近邻。
6. 只有双方互为 Top-K 且相似度 `>= 0.925`，才生成无向边。
7. 对图做连通分量。
8. 连通分量人数 `>= 3` 才输出候选团伙簇。
9. 当前 `shadow_only=true`，只生成调查候选，不自动拦截或写入正式风险标签。

## 8. 阈值优化空间

### 8.1 质量阈值

质量阈值有较大业务调节空间：

| 覆盖率 | 质量阈值 | PLDA EER | Top-1 |
|---:|---:|---:|---:|
| 100.00% | 0.475698 | 8.69% | 73.73% |
| 90.01% | 0.666611 | 8.25% | 74.10% |
| 80.02% | 0.696756 | 7.40% | 77.01% |
| 70.03% | 0.714726 | 7.82% | 77.16% |
| 60.04% | 0.731500 | 6.59% | 78.85% |
| 50.05% | 0.743804 | 6.92% | 78.08% |

当前平台选择约 60% 覆盖率点，偏向低 EER。如果业务希望减少人工复核，可以评估 80% 覆盖率附近的质量阈值。

### 8.2 PLDA 与 AS-Norm

离线对比结果：

| 后端 | 覆盖率 | EER | Top-1 |
|------|---:|---:|---:|
| 裸余弦 | 100% | 11.65% | 59.22% |
| 外部 AS-Norm | 100% | 10.38% | 61.44% |
| PLDA | 100% | 8.69% | 73.73% |
| PLDA + AS-Norm 等权融合 | 100% | 8.47% | 71.29% |
| PLDA + AS-Norm 测试集内最佳融合 | 100% | 8.26% | 72.25% |

结论：

- PLDA 已明显优于裸余弦和单独 AS-Norm。
- PLDA + AS-Norm 融合有进一步降低 EER 的空间。
- 测试集内最佳融合权重偏乐观，不能直接上线，需要独立冻结集验证。

### 8.3 黑产 1:N

黑产 1:N 当前阈值低误报优先。功能测试中 50 库规模下：

| 指标 | 值 |
|------|---:|
| 阈值 | 0.903645 |
| Top-1 召回 | 78.40% |
| Top-5 召回 | 90.40% |
| 端到端黑产召回 | 31.00% |
| 非黑综合误报 | 0.20% |

如果业务目标是多捞可疑线索，可下调阈值或放宽进入黑产检索的前置条件，但复核量和误报会增加。

### 8.4 N:N 团伙簇

当前 N:N 阈值是高精度低召回策略。历史参数扫描显示：

| 阈值 | Top-K | 精确率 | 召回率 | 误簇数 | 说明 |
|---:|---:|---:|---:|---:|------|
| 0.925 | 2 | 100.00% | 10.71% | 0 | 当前保守策略 |
| 0.900 | 2 | 36.36% | 42.86% | 2 | 召回提升，误报增加 |
| 0.875 | 3 | 4.09% | 100.00% | 8 | 多捞线索但误报明显 |

当前平台作为影子调查工具，保持 0.925 更稳。如果用于线索挖掘，可在离线报告中额外输出低阈值候选，但不建议自动决策。

## 12. 人工复核

当前人工复核定位为外部流转，不改变声纹平台内部模板、核验结论或风险标签。平台只记录复核任务和流转状态，供其他系统继续处理。

当前会创建复核任务的场景：

| 复核类型 | 触发场景 |
|------|------|
| `self_check_gray_zone` | 客户 1:1 PLDA 分数落在拒绝阈值和通过阈值之间，平台无法自动判断是否本人 |
| `black_search_gray_zone` | 黑产 1:N Top-1 分数落在灰区下界和命中阈值之间，平台无法自动判断是否应命中黑产 |

其他场景的处理原则：

- 客户首次录音不再依赖人工复核，质量达标且黑产 1:N 清白时自动入库。
- 客户明确 1:1 通过且黑产清白时自动补充活动模板。
- 客户明确非本人、明确黑产命中或质量未达标时保留平台标签和处理状态，不进入人工复核队列。
- 黑产入库录音质量达标时自动激活黑产模板；质量不达标时不激活。
- 角色识别失败或无法生成 embedding 时记录失败状态和审计事件，不进入人工复核队列。

复核接口仍提供“通过/拒绝”按钮，但该结果只代表外部系统流转状态，不反向修改平台声纹库。

## 14. 已知限制与风险

### 14.1 单进程存储限制

`JsonStateStore` 是面向单进程写入的本地 JSON 状态库。线程内写入有锁，但多个服务进程同时写同一个 `platform_state.json` 会有覆盖风险。

建议：

- 当前只运行一个平台实例。
- 生产化前迁移到数据库或引入跨进程文件锁。

### 14.2 权限与安全

当前 HTTP 服务已增加本地登录会话、账号角色和数据权限控制。仍需注意：初版会话适用于本机单实例平台，尚未接入企业统一认证、强密码策略、登录失败锁定和 HTTPS。

建议：

- 仅本机访问。
- 不直接暴露到内网多人环境或公网。
- 如需多人生产使用，先接入统一认证、HTTPS、登录审计和更细粒度的操作授权。

### 14.3 录音与客户主键敏感

当前平台根据业务核对要求保留客户主键，同时上传录音和分轨音频保存在本地处理目录。

建议：

- `data/processed/platform/` 按敏感目录管理。
- 报告和截图中避免暴露客户明细和本地音频路径。
- 明确数据保留周期和清理策略。

### 14.4 `pickle` 和实验缓存

部分历史库和离线脚本使用 `pickle.load` 或 `allow_pickle=True`。

建议：

- 只加载本地可信产物。
- 不接收外部来源 pickle 文件。
- 后续可逐步迁移为 `.npz`、JSON 或结构化数据库。

### 14.5 外部复核边界

当前复核任务只作为外部系统流转记录，不反向修改平台模板、录音状态或核验结论。

建议：

- 对接外部系统前明确流转协议、回传字段和对账口径。
- 平台侧保留复核任务状态、处理人和审计事件。
- 不把外部复核结果作为自动入库或自动拦截依据，除非后续版本重新设计闭环规则。

### 14.6 UI 响应式问题

已发现：

- 平板侧栏显示内部英文标识。
- 手机端只保留前四个导航入口。

建议：

- 平板侧栏使用 `data-mobile` 或图标 tooltip。
- 手机端增加更多菜单入口或底部导航。

## 15. 后续优化建议

优先级建议：

| 优先级 | 事项 | 原因 |
|------|------|------|
