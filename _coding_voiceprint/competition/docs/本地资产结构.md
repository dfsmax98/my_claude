## 数据分级

| 分级 | 资产 | 要求 |
|------|------|------|
| 敏感数据 | 原始录音、客户标识、ASR全文、embedding、客户矩阵、黑产声纹库、私有清单 | 仅授权环境本地保存，不提交普通Git，不在报告中暴露明细 |
| 内部模型 | 角色模型、PLDA模型、质量模型、背景库快照 | 版本冻结；获准发布的小型文件使用Git LFS |
| 外部运行资产 | ModelScope模型、降噪模型 | 保留来源和许可证信息；因体积较大不进入普通Git |
| 可发布资产 | 源码、测试、配置、脱敏摘要和Markdown文档 | 普通Git跟踪，提交前执行敏感信息检查 |
| 可再生产物 | `reports/`和`_temp/` | 默认忽略；重要结论脱敏后复制到`docs/reports/` |

## Git边界

- 当前本地改动尚未提交或推送，`master`关联`origin/master`。

- `models/role/**/*.joblib`与`models/backend/**/*.npz`配置为Git LFS。
- `data/raw/`、`data/processed/`、`models/runtime/`、`reports/`和`_temp/`中的实际资产保持忽略。
- `data/manifests/*_private.csv`始终忽略，禁止通过强制添加绕过该规则。

## 维护规则

1. 原始录音目录只读使用，不直接覆盖；新批次使用独立批次目录。
2. 处理数据按样本集、模型版本或日期命名，并在`configs/project.json`固定正式输入。
3. 角色模型、embedding模型和打分后端分别管理版本，阈值不得跨后端复用。
4. 正式基线保留在`docs/reports/`，一般运行输出留在`reports/`，临时音频和日志只放入`_temp/`。
5. 资产变更后重新生成清单并校验SHA-256；不要手工修改机器生成的摘要。
6. 原项目和比赛工程继续保持复制关系，不移动或删除原 `声纹对比/` 资产。
