# 客诉录音分角色 N×N 声纹评估报告

> 最终口径：先用 ASR 判定每通录音的客户声道与客服声道，再分别做“客户对客户”和“客服对客服”声纹矩阵；不再用固定 `L-L` / `R-R` 作为结论口径。

## 样本概况

- 成功录音：985 通
- 客户标识：500 个
- 双通客户：485 个
- 单通客户：15 个
- ASR 角色识别失败：0 通
- 声纹模型：CAM++，192 维归一化 embedding

## ASR 判角策略

- 先转录双声道前 30 秒；话术差异达到高置信且不违背右声道客户先验时，直接确定客户/客服角色。
- 30 秒结果为中/低置信，或与右声道客户先验冲突时，扩展到 120 秒。
- 120 秒后仍缺一方或低置信时，不再跑全量 ASR，直接进入人工复核。
- ASR 仅用于角色判断；转译文本不落盘，只保留关键词计数、字符数、时长、置信度和最终声道。

## 角色识别结果

- 成功识别：985 通
- 客户声道：R=712 通，L=273 通
- 30 秒完成：426 通
- 120 秒完成：559 通
- 全量 ASR：0 通
- 阶段判断不一致：229 通
- 待人工复核：72 通

## 解读

- 客户对客户矩阵是真正用于客户身份一致性评估的主口径：同客户配对表示同一客户两通录音的客户侧声纹。
- 客服对客服矩阵用于观察客服侧声音是否污染客户侧检索，或是否存在大量重复坐席；由于当前没有客服工号真值，不能把该矩阵解释为客服本人识别准确率。
- 低置信 72 通已保留在全量矩阵中并标记待复核；正式上线或建库时应优先使用可信子集，低置信样本不硬判入库。
- 固定声道 `L-L` / `R-R` 结果仅作为历史基线文件保留，不再作为本轮结论依据。

## 产物

- `adaptive_roles.json`：自适应 ASR 角色识别检查点，不包含转译文本。
- `adaptive_role_labels.csv`：客户/客服声道、置信度、最终阶段和复核标记。
- `customer_nxn_matrix.npz` / `customer_nxn_matrix.csv`：客户对客户 N×N 矩阵。
- `agent_nxn_matrix.npz` / `agent_nxn_matrix.csv`：客服对客服 N×N 矩阵。
- `role_metrics.json`：客户侧与客服侧全量/可信子集指标。
- `customer_metrics.json`：客户对客户指标，保留兼容旧脚本。
- `agent_metrics.json`：客服对客服指标。
- `分角色ASR评估报告.md`：分角色 ASR 评估明细。
- `channel_embeddings.npz`：每通录音 L/R 原始 embedding 与元数据，用于按角色抽取矩阵。
- `failures.json`：固定声道 embedding 阶段失败明细。
