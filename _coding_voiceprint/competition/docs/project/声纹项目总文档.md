# 声纹对比工具

基于开源 SpeechBrain ECAPA-TDNN 模型的声纹相似度比对工具，用于反欺诈场景下的说话人识别（代理黑产、S4声音比对异常等标签）。

把两段录音各编码成一个 192 维声纹向量，算余弦相似度，超过阈值判定为「同一人」。

> 2026-08-20 当前口径：模块已增加基于 FunASR 与训练语料自动学习的客服/客户文本角色模型，近期批次声纹使用 CAM++ 生成192维向量。下方ECAPA内容保留为早期基础能力说明，角色识别与近期批处理以“九、客服/客户话术角色模型”为准。

---

## 一、能做什么

| 能力 | 说明 | 脚本 |
|------|------|------|
| 1:1 比对 | 判断两段录音是否同一人 | `voiceprint_compare.py verify` |
| 1:N 检索 | 一段待查录音 vs 声纹库，返回最相似的若干条 | `voiceprint_compare.py search` |
| 建声纹库 | 批量把目录内音频注册进库 | `voiceprint_compare.py enroll` |
| 批量评测 | N×N 相似度矩阵 + 按真实标签算区分度、建议阈值 | `eval_matrix.py` |
| 格式转换 | m4a 等 → 16kHz 单声道 wav | `convert_to_wav.py` |
| 客服/客户角色识别 | 仅根据双声道ASR文本判断客服与客户，低置信时拒识 | `common/text_role.py` |
| 近期录音批处理 | 角色判断后提取客户侧CAM++向量 | `pipelines/process_recent_voiceprints.py` |
| 全量客户声纹库滚动构建 | 按`begin_time >= 2025-01-01`、`call_time_length >= 20`、`cust_no IS NOT NULL`筛选，键集分页滚动构建客户侧向量库 | `pipelines/build_full_customer_voiceprint_library.py` |

## 二、环境准备（首次）

### 1. 依赖安装

```bash
# CPU 版 torch（体积小，约 124MB；不要用默认源，默认源含 CUDA 达 2.5GB）
pip install torch torchaudio --index-url https://download.pytorch.org/whl/cpu

# 其余依赖
pip install speechbrain imageio-ffmpeg soundfile numpy

# huggingface_hub 必须用 0.x（1.x 与 speechbrain 1.1 不兼容）
pip install "huggingface_hub<1.0"
```

### 2. Windows 额外要求

- **VC++ 运行库**：torch 2.12 需要 VS2022 运行库（≥14.40）。若 `import torch` 报 `WinError 1114`，装
  [vc_redist.x64.exe](https://aka.ms/vs/17/release/vc_redist.x64.exe) 后重启终端。
- **无需系统 ffmpeg**：`convert_to_wav.py` 用 `imageio-ffmpeg` 自带的二进制解码 m4a。

### 3. 模型下载（国内网络）

首次运行会自动从 HuggingFace 下载 ECAPA 模型（~80MB）。国内直连 HF 会被墙，**必须走镜像**，运行时加环境变量：

```bash
HF_ENDPOINT=https://hf-mirror.com python eval_matrix.py ...
```

模型下载后缓存在 `pretrained_models/`，之后无需重复下载、也无需再联网。

## 三、使用步骤

### 步骤 1：转码为 wav

把录音（m4a/mp3 等）放到本目录，转成 16kHz 单声道 wav（输出到 `wav_16k/`）：

```bash
python convert_to_wav.py
```

> ECAPA 模型要求 16kHz。`convert_to_wav.py` 默认处理当前目录所有 `.m4a`。

### 步骤 2A：批量评测 / 标定阈值（推荐先做）

跑 N×N 相似度矩阵，用真实标签验证模型在你数据上的区分度：

```bash
# --labels 传真实说话人标签：文件名=人物id
HF_ENDPOINT=https://hf-mirror.com PYTHONIOENCODING=utf-8 \
  python eval_matrix.py --labels "1=A,1_1=A,3=A,2=B,4=B" --threshold 0.30
```

输出：相似度矩阵 + 同人对/异人对明细 + 区分度小结（同人最低分、异人最高分、建议阈值）。

不传 `--labels` 时按文件名下划线前缀自动分组（如 `zhangsan_1` → `zhangsan`）。

### 步骤 2B：单次 1:1 / 建库 / 1:N 检索

```bash
# 1:1 —— 两段录音是否同一人
HF_ENDPOINT=https://hf-mirror.com python voiceprint_compare.py verify a.wav b.wav

# 建库 —— 目录下所有音频注册进声纹库（文件名=说话人id）
HF_ENDPOINT=https://hf-mirror.com python voiceprint_compare.py enroll ./enroll_wavs voiceprint_db.pkl

# 1:N —— 待查录音 vs 声纹库，返回 topk 最相似
HF_ENDPOINT=https://hf-mirror.com python voiceprint_compare.py search query.wav voiceprint_db.pkl --topk 5
```

> 注意：`voiceprint_compare.py` 用 torchaudio 读音频，torchaudio 2.11 默认后端需 `torchcodec`。
> 若报 torchcodec 相关错误，先用 `convert_to_wav.py` 把输入转成标准 wav，或参照 `eval_matrix.py` 改用 soundfile 读取。

## 四、结果怎么看

- **余弦相似度**范围约 -1~1，越高越像。
- **同一个人**的两段录音相似度应明显高于**不同人**。
- 阈值判定：`相似度 ≥ 阈值` → 同一人。
- 理想情况：所有「同人对最低分」都 > 所有「异人对最高分」，两者之间的间隔就是可靠阈值的依据（取中点）。

---

## 五、阈值必须自己标定 ⚠️

代码默认阈值 **0.30** 是 VoxCeleb（英文朗读）经验值，**不能直接用于生产**：

- 你的场景是中文、可能是电话催收录音（8kHz 窄带、有信道噪声），最优阈值不同。
- 标定方法：准备一批已知「同一人 / 不同人」的录音对，跑 `eval_matrix.py --labels` 看同人/异人分数分布，取让误报和漏报平衡的阈值。

### 提升准确率的建议

1. **每段录音尽量长**（≥10 秒有效语音），太短声纹向量不稳。
2. **每人多给几段**（3~5 段）不同录音来标定，不要用复制文件。
3. **电话窄带录音**：ECAPA 是英文朗读训练的，跨语言 + 窄带会掉点。效果不好时换中文/电话场景微调模型（**3D-Speaker**、**WeSpeaker**）。
4. 可先做降噪 / VAD 去静音再比对。

## 六、历史测试记录

### 2026-07-02 首次真实录音实测

**样本**：5 个 m4a（`1/1_1/2/3/4`），真实标签 A={1,3}、B={2,4}（`1_1` 是 `1` 的复制品）。

**相似度矩阵**：

|       | 1 | 1_1 | 2 | 3 | 4 |
|-------|-----|-----|-----|-----|-----|
| **1**   | 1.000 | 1.000 | 0.173 | 0.312 | 0.285 |
| **1_1** | 1.000 | 1.000 | 0.173 | 0.312 | 0.285 |
| **2**   | 0.173 | 0.173 | 1.000 | 0.106 | 0.477 |
| **3**   | 0.312 | 0.312 | 0.106 | 1.000 | 0.053 |
| **4**   | 0.285 | 0.285 | 0.477 | 0.053 | 1.000 |

**关键结果**（按真实标签）：

| 类型 | 配对 | 相似度 |
|------|------|--------|
| 同人 | 1 vs 3（A） | 0.312 |
| 同人 | 2 vs 4（B） | 0.477 |
| 异人 | 1 vs 4 | 0.285（异人对最高） |
| 异人 | 1 vs 2 | 0.173 |
| 异人 | 2 vs 3 | 0.106 |
| 异人 | 3 vs 4 | 0.053 |

**结论**：
- 阈值 0.30 下，4 段真实录音**全部分类正确**，模型方向可用。
- 但同人最低（0.312）与异人最高（0.285）**间隔仅 0.027**，过窄不稳，样本增多极可能被击穿。
- A 某同人分 0.312 偏低（正常应 0.5~0.8），疑因录音过短 / 信道差 / 内容差异大。
- **当前样本不足以可靠标定阈值**，需每人 3~5 段 ≥10 秒的不同录音；电话窄带建议换中文模型。

## 九、客服/客户话术角色模型

### 9.1 当前模型

当前角色识别版本为 `role-text-v1-20260820`，用于在双轨电话录音中确定客服声道和客户声道。模型流程如下：

1. 将录音拆分为L/R两个声道。
2. 使用FunASR分别提取两侧临时文本及有效语音摘要。
3. 使用字符2至6元TF-IDF和Logistic Regression计算两侧客服概率。
4. 选择客服概率较高的一侧作为候选客服声道，另一侧作为候选客户声道。
5. 两侧概率差低于冻结阈值 `0.817575` 时返回待复核，不强行判断。

模型输入只包含ASR文本，不包含呼叫方向、左右声道先验、客户标识或测试标签。呼叫方向只用于构造离线代理标签和分层评估，旧的“右声道固定为客户”先验已禁止启用。

### 9.2 数据质量规则

每个声道必须同时满足：

- ASR字符数不少于20。
- 有效语音时长不少于5秒。

质量状态及处理方式：

| 状态 | 条件 | 处理方式 |
|------|------|------|
| 有效双边对话 | L/R均达到门槛 | 进入角色识别 |
| 单边有效语音 | 仅一侧达到门槛 | 剔除，不生成正式客户向量 |
| 无有效对话 | 两侧均未达到门槛 | 剔除，不生成正式客户向量 |
| 低置信双边对话 | 双边有效但概率差低于阈值 | 标记待复核，不进入正式向量库 |

近期1万通录音质量分层结果：有效双边对话9,742通、单边有效语音185通、双方均无足够有效对话73通。

### 9.3 训练语料与防泄漏

- 从有效双边对话中冻结抽取4,000通，其中呼入2,764通、呼出1,236通。
- 413通因缺少客户身份哈希、无法证明客户级隔离而从训练和准确率分母剔除。
- 最终3,587通按客户身份SHA-256固定划分：训练2,484通、验证525通、测试578通。
- 训练、验证、测试之间的客户交叉数为0。
- 超参数和拒识阈值只使用训练集与验证集确定，冻结测试集只执行一次最终评估。
- 完整ASR训练文本只保存在`_temp/role_text_corpus_20260820/`，正式模型、报告和预测结果不保存完整转录。

### 9.4 自动学习的话术

模型从训练语料自动学习客服正向表达和客户反向表达，不使用人工预设答案直接判定角色。

| 角色方向 | 高权重表达示例 | 模型作用 |
|------|------|------|
| 客服正向 | `先生`、`这边`、`帮您`、`我们`、`给您`、`请问`、`女士`、`来电` | 提高该声道的客服概率 |
| 客户反向 | `你们`、`给我`、`帮我`、`怎么`、`我想`、`没有`、`你说` | 降低该声道的客服概率 |

完整权重清单位于`reports/role_text_model_20260820/learned_phrases.csv`。

### 9.6 生产接入与向量库更新

- 推理接口：`common/text_role.py`中的`classify_features()`和`classify_audio()`。
- 批处理入口：`pipelines/classify_roles_adaptive.py`，已接入纯文本角色模型并禁止右声道客户先验。
- 模型文件：`checkpoints/role_text_v1_20260820/role_text_model.joblib`。
- 模型输出：客服声道L/R、客户声道L/R或待复核，并返回两侧客服概率、概率差和冻结阈值。
- ASR全文只在推理内存中使用；角色检查点仅保存字符数、有效语音时长、模型概率和角色结果。

现有客户向量按旧角色结果选择声道后生成，因此新模型上线时必须全量重新执行角色判断。CAM++模型未变化，不要求所有录音无条件重提embedding：新旧客户声道一致时可以复用原向量，声道变化时必须从新客户声道重新提取；无有效对话、单边对话和仍待复核样本不得进入正式客户向量库。完成后需按新角色结果重建客户向量索引和N×N矩阵，并以新版本目录输出，验收前不得覆盖旧库。

## 十、声纹后端优化通用模板

本章节用于复用“外部背景库 AS-norm + PLDA 打分器 + embedding 质量评分”的优化流程。模板默认只评估目标角色的声纹，例如客户侧；客服侧是否评估必须在任务范围中明确，不能将两侧指标混在同一结论中。

### 10.1 适用范围与目标

| 项目 | 填写内容 |
|------|------|
| 业务场景 | `{场景名称}` |
| 目标角色 | `{客户/客服/其他}` |
| embedding模型 | `{模型名称}` |
| embedding版本 | `{模型版本}` |
| 角色模型版本 | `{角色模型版本}` |
| 评估集 | `{评估矩阵路径}` |
| 训练集 | `{PLDA训练向量路径}` |
| 外部背景库 | `{cohort目录或快照路径}` |
| 目标指标 | `{EER/TAR/FAR/Top-1/覆盖率}` |
| 生产约束 | `{允许的漏报、误报、延迟和覆盖率}` |

优化目标不是单纯追求最低 EER，而是在明确覆盖率和业务风险的前提下，选择可解释、可复现、可回滚的打分与质量分流方案。

### 10.2 输入数据契约

#### A. 评估矩阵 `NPZ`

必须至少包含以下字段：

| 字段 | 类型 | 约束 |
|------|------|------|
| `recording_ids` | 一维字符串数组 | 每条录音唯一 |
| `identities` | 一维字符串数组 | 与录音一一对应，评估真值标签 |
| `embeddings` | `N x D` 数值数组 | 维度一致、有限值、建议行归一化 |

评估矩阵必须只保留目标角色的 embedding。角色识别失败、单边有效、待复核或无法证明角色正确的录音，应在进入矩阵前分流，并记录剔除原因。

#### B. PLDA 训练集 `NPZ`

必须至少包含：

| 字段 | 类型 | 约束 |
|------|------|------|
| `embeddings` | `N x D` 数值数组 | 与评估集维度和 embedding 版本一致 |
| `identity_sha256` | 一维字符串数组 | 客户/说话人身份哈希，不保存明文身份 |
| `needs_review` | 一维布尔数组 | 训练默认只使用 `false` |

训练集需包含多个身份，且每个训练身份至少两条独立录音。单条身份不能估计类内变化，不应作为 PLDA 训练身份。

#### C. 外部背景库 `cohort`

正式背景库每条记录至少包含：

```json
{
  "identity_sha256": "{身份哈希}",
  "embedding_model": "{embedding模型}",
  "embedding_model_version": "{embedding版本}",
  "role_model_version": "{角色模型版本}",
  "formal_index_eligible": true
}
```

背景库必须与评估集身份隔离。生产使用前应冻结 cohort 快照并记录样本数、身份数、模型版本、剔除的重叠身份数和快照路径。

### 10.3 强制防泄漏规则

- PLDA 训练身份与最终评估身份交集必须为 0；交集检查使用身份哈希，不使用录音文件名猜测。
- 外部 cohort 不得包含评估身份；同一身份的其他录音也必须剔除，不能只剔除同一条录音。
- PLDA 维度、正则化、质量阈值和后端阈值只能使用训练集/验证集确定，不能根据最终测试集反向挑选。
- 质量模型必须按身份分组做交叉验证；同一身份的多条录音不能分到不同折后再用一条预测另一条造成泄漏。
- 测试集只执行一次最终评估。任何参数修改后都应重新生成版本化评估产物。
- 训练、评估和背景库必须固定 embedding 模型版本；版本不一致时禁止直接混训或直接计算分数。

### 10.4 推荐处理流程

```text
角色识别与质量分流
        |
        v
目标角色 embedding + 身份哈希
        |
        +--> 裸余弦基线
        |
        +--> 独立背景库 --> 外部 AS-norm
        |
        +--> 独立训练身份 --> PLDA 训练 --> PLDA 分数
        |
        +--> 时长/ASR/角色/声学特征 --> OOF 质量评分
        |
        v
独立冻结集重新标定阈值
        |
        v
全量召回 / 高置信自动命中 / 人工复核 / 拒识
```

### 10.5 后端方案

#### A. 裸余弦基线

保留原始余弦作为回滚、监控和对照口径：

```python
score = normalize(embedding_a) @ normalize(embedding_b)
```

基线报告至少包含 EER、EER 阈值、TAR、FAR、FNR、Top-1、同人对数量和异人对数量。

#### B. 外部 AS-norm

对每条评估 embedding 与外部 cohort 计算分数，取最高 `K` 个 cohort 分数估计局部均值和标准差，再对两侧分数做对称归一化。

```text
cohort_scores(a) = cosine(a, cohort)
mu_a, sigma_a = top_k_stats(cohort_scores(a))
asnorm(a,b) = 0.5 * ((cosine(a,b)-mu_a)/sigma_a
                    + (cosine(a,b)-mu_b)/sigma_b)
```

`K` 不是固定常数。模板建议测试 `{25, 50, 100, 200}` 等候选值，并在独立验证集选择；最终生产应冻结 `K`、cohort 版本和新分数阈值。AS-norm 分数不是余弦分数，不能沿用余弦阈值。

#### C. PLDA 打分器

PLDA 适用于有足够重复身份、且身份标签可信的训练集。推荐顺序：

1. 对训练 embedding 做归一化和降维候选搜索。
2. 只在训练身份内部做分组交叉验证，选择维度和正则化。
3. 估计类内协方差和类间协方差，必要时做正定化和收缩。
4. 在完全隔离的评估集输出 PLDA 分数。
5. 在独立验证集标定 PLDA 阈值，测试集只做最终报告。

训练身份少于 `{PLDA最小身份数}`、重复录音不足或标签噪声无法控制时，不应强行上线 PLDA；可先使用裸余弦或外部 AS-norm，并补充训练数据。

### 10.6 embedding 质量评分模板

质量评分用于判断 embedding 是否适合自动命中、注册模板或只参与宽松召回。建议分为三类特征：

| 特征类别 | 示例特征 | 当前状态 |
|------|------|------|
| 语音量 | 客户有效语音秒数、VAD保留比例 | 必选/可选 |
| 文本与角色 | ASR字符数、角色模型margin、阶段稳定性 | 有角色模型时必选 |
| 声学与向量 | SNR、RMS、削波率、静音率、分段embedding一致性、cohort统计 | 有原始音频时补充 |

当前实现 `pipelines/evaluate_customer_plda_quality.py` 使用以下六项特征作为模板示例：

```text
log_customer_speech_seconds
log_customer_asr_chars
role_margin
role_stage_count
external_cohort_topk_mean
external_cohort_topk_std
```

质量模型的训练标签应来自明确的业务成功标准，例如“PLDA Top-1 是否召回同身份”，并使用身份互斥 OOF 预测。没有可靠标签时，不应把人工门槛或当前测试集结果伪装成质量模型效果。

推荐分流：

| 质量等级 | 处理方式 |
|------|------|
| 高质量 | 可参与高置信自动命中或正式模板注册 |
| 中质量 | 参与候选召回，命中后进入二次校验 |
| 低质量 | 人工复核、重新录音或仅作宽松召回 |
| 无法计算 | 不进入正式索引，保留失败原因 |

质量剔除必须同时报告保留率和效果，禁止只报告过滤后的 EER。建议至少输出 `100%/90%/80%/70%/60%/50%` 覆盖率曲线，并选择符合业务最低覆盖率的点，而不是直接选择最低 EER。

### 10.7 统一评估指标与阈值标定

每个后端至少输出：

| 指标 | 说明 |
|------|------|
| EER | FAR 与 FNR 接近时的平衡错误率 |
| EER阈值 | 仅对应当前后端分数空间 |
| TAR@阈值 | 同人样本被接受的比例 |
| FAR@阈值 | 异人样本被错误接受的比例 |
| FNR@阈值 | 同人样本被错误拒绝的比例 |
| Top-1 | 在身份存在多条录音时的最近邻识别准确率 |
| 覆盖率 | 质量分流后仍参与自动处理的录音比例 |
| 同人/异人对数量 | 判断指标是否由极少数配对支撑 |

阈值标定必须单独执行。推荐保留三档业务阈值：

```text
高风险命中阈值: 目标 FAR <= {FAR上限}
常规判定阈值:   目标 EER/TAR/FAR 组合为 {业务目标}
宽松召回阈值:   目标召回率 >= {召回率下限}
```

不要把 EER 误认为某个固定阈值下的错误率，也不要跨余弦、AS-norm、PLDA 分数空间复用阈值。

