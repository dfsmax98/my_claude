## 一、系统能做什么

1. **固化的客户声纹提取**：双轨拆分→取客户声道→(可选降噪)→CAM++ embedding，单一函数入口。
2. **离线批量建库**：跑历史录音，建「客户声纹库」+「黑产声纹库」。
3. **实时核验**：新录音进来 → 1:1 判是否本人 → 1:N 查是否黑产。
4. **声学画像**（性别/年龄/情绪）：接口预留，本期未实现。

## 二、环境约束（踩过的坑，务必遵守）

- **Python 3.14**，venv 在 `d:/my_claude/credit_analysis_demo/venv`。
- 运行统一加环境变量：`MODELSCOPE_CACHE=./ms_cache PYTHONIOENCODING=utf-8`（在 `声纹对比/` 下执行）。
- **禁用 `modelscope.pipelines`**：Py3.14 上导入即段错误（退出码 139）。所有模型走 `funasr.AutoModel` 或独立 pip 包。
- 声纹模型：**CAM++**（FunASR，192 维，L2 归一化，点积=余弦），已验证优于 ECAPA。
- HuggingFace 被墙：需要时加 `HF_ENDPOINT=https://hf-mirror.com`；ModelScope 国内直连。
- **CPU-only**（torch 2.12+cpu）；faiss/onnxruntime 未装。
- 输入录音：**8k 双声道电话**（一方一声道，`speaker0=左L / speaker1=右R`）。
- Windows shell 首行 `.bashrc: $'\377\376export'` 报错是环境噪声，无害；中文文档一律用 Python 以 UTF-8 读写。

## 四、核心：固化提取管线

`common/extract.py`，离线建库与实时核验**共用同一条链**（保证"建库怎么提、核验就怎么提"）：

```python
from common.extract import extract_customer_embedding
emb          = extract_customer_embedding("call.mp3")                    # -> (192,)
emb, meta    = extract_customer_embedding("call.mp3", return_meta=True)  # meta含声道/置信/质检
```

链路：①双轨校验（非双轨抛 `NotDualTrackError`）→ ②拆左右声道 → ③`role_id.decide_role` 定客户声道 → ④VAD(可选) → ⑤质检(有效语音<3s 判 reject) → ⑥降噪(可开关) → ⑦CAM++ embedding。

`meta` 字段：`customer_ch / role_confidence / dur / quality / denoise_applied / model`。

### 自适应 ASR 判角策略

批量评估或右声道先验需要复核时，使用 `pipelines/classify_roles_adaptive.py`。

<!-- 2026-07-31: v1 使用业务主题词密度，并仅将低置信送入复核；实测会把客户重复提及的“平台、欠款、费用”等词误当成坐席证据。 -->

- 先转录双声道前 30 秒；只有客服身份、核验、服务动作等专属话术达到高置信，且不违背右声道客户先验时，才直接确定角色。
- 30 秒结果非高置信，或与右声道客户先验冲突时，扩展到 120 秒。
- 120 秒后仍非高置信时才跑全量；禁用全量 ASR 时直接进入人工复核。中低置信样本不进入正式客户/客服矩阵。
- 首次发声只在 ASR 返回真实句级时间戳且双方时间差不少于 0.3 秒时作为中置信佐证；没有时间戳不得生成“先开口”证据。
- 双方均无客服专属话术时必须标记低置信，不得因分母为零产生高置信。
- 默认角色检查点不保存转译全文，只保存数值摘要。需要人工复核时运行 `pipelines/export_channel_transcripts.py`，按声道增量保存 WAV、JSON 和中文转录稿。

```powershell
python pipelines/export_channel_transcripts.py <录音目录> `
  --output-dir <复核输出目录> --duration 30 `
  --role-checkpoint <adaptive_roles.json>
```

## 五、三条业务管线用法

### 离线建客户库
```bash
MODELSCOPE_CACHE=./ms_cache PYTHONIOENCODING=utf-8 \
  python pipelines/build_customer_db.py <录音目录> --db data/customer_db.pkl
```
遍历录音→固化提取→按客户号归组→`cluster` 定主簇（本人）→写库+报告。支持断点续跑（emb 缓存）。非双轨/质检 reject/角色低置信的录音隔离到"待复核"，不入库。

### 建/迁移黑产库
```bash
python pipelines/build_black_db.py --src black_db.pkl --db data/black_db.pkl
```

### 实时核验（常驻服务）
```python
from pipelines.verify_realtime import VoiceprintVerifier
v = VoiceprintVerifier("data/customer_db.pkl", "data/black_db.pkl")  # 预加载模型+库
res = v.verify("new_call.mp3", cust_no="{客户号}")
```
返回 `self_check`（本人/存疑/非本人告警/证据不足）+ `black_search`（1:N 黑产命中）。命令行单测：
```bash
MODELSCOPE_CACHE=./ms_cache python pipelines/verify_realtime.py <录音> --cust-no <客户号>
```

## 六、声纹库 Schema

库为 pickle，`records` 扁平列表 + 顶层 `model`，向后兼容旧 `black_db.pkl`。

**客户库**（身份单元 = 客户号）：
```
{"model":"cam++", "schema_version":2,
 "identities": {"<客户号>": {"primary_cluster":[rec_id]|"undecided", "aux_clusters":[[...]],
                            "phones":[...], "n_calls", "n_voices", "status"}},
 "records": [{"id":"<客户号>::<call>::<seg>", "emb":(192,), "cust_no", "phone",
              "call_id","seg","cluster":"primary|aux", "quality","role_confidence","denoise","source","added"}]}
```
**黑产库**：records 加 `actor_id`（同一代理多通聚一个）/`phones`/`tag`/`reviewer`（入库审核留痕）。

**检索**：`vpdb.search_by_identity(q, db, id_key)` 按身份取模板集最大余弦（多模板 max-pooling），命中的是客户号/actor 而非单条 record。

## 七、阈值与决策（已标定，8k 电话专用）

标定自 0728 批（10 客户，同人=同号两段，异人=跨号）：EER≈**10%**，EER 点阈值 **0.725**，保守判同阈值 **0.751**（异人95分位），同人5分位 **0.634**。

**三段决策带**（不靠单一硬阈值）：
- `≥ 0.751` → 判同 / 命中
- `0.634 ~ 0.751` → **存疑**（需叠加文本/业务证据，落人工）
- `< 0.634` → 判异 / 未命中

聚类连边阈值同用 0.725（与判同同源）。**仅适用 8k 电话**，高清语音需另标。8k 窄带有地板效应（异人也可高到 0.8），故靠三段决策 + 多模板 + 三重验证，不单凭分数定案。

## 八、降噪：实测不纳入

`common/denoise.py` 保持 `ENABLED=False`。A/B 实验（2026-07-29）结论：FRCRN/clearvoice 在当前 Py3.14 + numpy2.4 + CPU 环境处理真实客户声道**段错误/超时不可用**（合成音频能过、真实音频必崩）。详见 [0728/降噪AB实验结果.md](0728/降噪AB实验结果.md)。

主系统不依赖降噪，全部功能不受影响。重启降噪需：独立 GPU 环境 + numpy<2 隔离依赖，且仍须过 A/B 正收益判据（EER↓ + 同人5分位↑ + 异人95分位不↑）。

## 十、规模化与后续

- **当前**：pickle + numpy 矩阵检索（`embs @ q`），万级以下够用。
- **Faiss 迁移触发**（任一）：身份数 >约5万 / 实时 1:N P99 超标 / 内存装不下全量矩阵。届时 `pip install faiss`，只换 `vpdb` 检索底层（IndexFlatIP，内积=余弦），业务零改动。
- **打分升级**：余弦 → PLDA（后期，压 8k 跨信道地板效应）。
- **画像线**：`acoustic/profile.py` 接入 emotion2vec/性别/年龄时，第一步必做 import 冒烟测试（避开 pipelines 段错误）。
- **实时服务安全**：客户声纹=敏感生物特征，服务层需鉴权 + 存储加密；黑产入库要审核留痕。

## 十一、单通客户的已知边界

只有一通录音的客户号无法自证"本人 vs 代接"（主簇 undecided），1:1 核验对其返回"证据不足"而非误判，靠后续通话积累。角色识别在话术接近时（`role_confidence=低`）也隔离到人工，不硬判。
