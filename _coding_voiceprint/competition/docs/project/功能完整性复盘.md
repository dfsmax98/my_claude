# 声纹项目功能完整性复盘

> 复盘日期：2026-08-18。结论仅基于当前代码、部署产物、单元测试和现有离线评估报告。

## 总体结论

当前项目已经形成“客户声道识别 → CAM++ 声纹提取 → 1:1 本人核验 → 1:N 黑产检索”的离线技术链路，22 项单元测试全部通过。它可以继续用于离线回放、阈值研究和风险线索验证，但尚不具备直接生产上线条件。

主要原因不是缺少算法脚本，而是运行闭环和验收边界仍不完整：新 schema 的客户库和黑产库部署文件缺失，实时能力仅有 Python 类与 CLI，尚无 HTTP API、鉴权、加密、审核和任务治理；当前模型指标也不足以支持单独硬判。

## 评估边界

- 客户矩阵使用 `cust_no` 作为同人代理标签，不等同于人工确认的声纹真值。
- 黑产库测试使用真实客户录音构造离线身份库，用于验证程序链路，不等同于真实黑产标签验收。
- 团伙簇真值来自同一真实说话人的不重叠 30 秒片段。高精度参数未检出完整团伙，只适合继续影子运行。
- 当前检索耗时只包含内存矩阵检索，不包含 ASR 判角、音频处理和 CAM++ 模型推理，不能作为端到端实时延迟。

## 建议推进顺序

1. 生成并核验 schema v2 客户库和黑产库，补齐版本、备份、回滚与迁移校验。
2. 将 `VoiceprintVerifier` 封装为异步服务，加入鉴权、超时、并发隔离、结构化日志和敏感数据保护。
3. 建立跨时间、跨设备的人工同人 / 异人真值集，重新标定 1:1 与各黑产库规模阈值。
4. 团伙簇保持影子运行，仅输出人工调查候选，积累真实团伙标签后再评估上线。
5. 画像能力单独立项，先验证 8k 电话样本准确率，再决定是否进入主链路。
6. 以 `上线版说明.md` 和本复盘为当前基线，重写过期的根目录 `README.md` 与交接说明。
